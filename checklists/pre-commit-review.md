# 提交与 Review Checklist

提交代码或发起 review 前，必须逐项确认：

不适用的检查项需要标记为 `N/A` 并说明原因，不应直接忽略。

## 通用检查

- [ ] 需求范围、验收条件和非目标已经确认。
- [ ] 生成测试中的 `TODO` 已替换为真实业务场景，新增或修改的分支有相应测试。
- [ ] 已运行最小相关测试；生成器改动已运行 `python3 -m unittest discover -s tests -v`。
- [ ] 项目能够编译，且没有新增编译警告或静态检查错误。
- [ ] UI 改动复用了 `DesignTokens`，并检查深色模式、动态字体、本地化和可访问性。
- [ ] 配置、资源、文档和生成产物已与代码行为同步。
- [ ] 已暂存和未暂存 diff 只包含本次需求相关内容，未包含密钥、个人数据、构建产物或调试代码。
- [ ] 已执行 `./bin/iosflow checklist <项目目录> --purpose commit|review`，并确认自动检查通过。

## 订阅检查

- [ ] App Store Connect、StoreKit 配置、服务端与客户端的订阅项、product ID 和权益映射一致。
- [ ] 月付、年付、试用、促销与恢复购买等入口均匹配正确的订阅项，不会购买或解锁其他权益。
- [ ] 订阅价格、币种、计费周期、折扣与试用信息来自 StoreKit 有效商品数据，未硬编码展示价格。
- [ ] 订阅文案与实际价格、币种、周期、试用资格、自动续费和取消规则一致，本地化后仍保持一致。
- [ ] 用户选中的订阅项、按钮文案、发起购买的 product ID 与最终发放的权益逐项匹配。
- [ ] 购买成功、失败、取消、pending、恢复购买、过期、退款和宽限期状态均已验证，权益状态与交易结果一致。
- [ ] 订阅页已提供恢复购买、服务条款和隐私政策入口，并使用 Sandbox 或 StoreKit Configuration 验证。

## 数据打点检查

- [ ] 每个事件的名称、业务含义和指标口径与数据埋点文档一致。
- [ ] 打点位置与事件含义匹配：曝光在真实可见时上报，点击在用户操作时上报，结果在成功或失败确认后上报。
- [ ] 页面、按钮、订阅项和购买流程的关键节点打点完整，没有缺失、提前上报或错位上报。
- [ ] 事件参数名称、类型、枚举值和必填性与文档一致；订阅事件中的 product ID、价格、币种、周期和交易结果来自当前实际交易。
- [ ] 页面重复出现、连续点击、请求重试、前后台切换和交易回调不会导致重复或遗漏上报。
- [ ] 打点不包含 token、完整支付信息或未允许的个人数据，并遵循用户同意、ATT 和隐私配置。
- [ ] 已在调试日志或分析平台 DebugView 核对事件名、触发次数、触发顺序、参数值和上报环境。

`iosflow checklist` 负责可自动判断的前置检查，不能替代编译、测试和人工代码 review。
