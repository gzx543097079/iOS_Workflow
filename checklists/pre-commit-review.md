# 提交、推送与 Review 门禁

用户触发 Git 提交、推送或代码 review 时自动执行，不等待再次要求。

## 状态

- `✅`：已检查并通过。
- `❌`：检查不通过；必须停止提交或推送，并提示失败项和处理建议。
- `➖`：本次 diff 未影响或不适用；必须说明原因。

## 范围

- 提交：检查准备提交的 diff；存在暂存区时以暂存区为准。
- 推送：检查相对上游即将推送的提交，并确认工作区状态不会造成误判。
- 提交并推送：两个阶段均触发；范围未变化时可复用测试证据，但需重新确认状态。
- Review：检查 review 对应的完整 diff。

## 按影响读取

1. 始终读取 `checklists/core.md`。
2. 先检查 diff。涉及 StoreKit、商品、价格、付费墙、购买、收据、恢复购买、订阅状态或权益时，再读取 `checklists/subscription.md`；否则整个模块记为 `➖`。
3. 涉及事件上报、曝光、点击、分析 SDK、事件参数、埋点文档或遥测时，再读取 `checklists/analytics.md`；否则整个模块记为 `➖`。
4. UI、依赖等规则按 `AGENTS.md` 的任务路由读取，不因执行门禁而加载全部规范。

## 输出与执行

- 每个适用项输出 `✅` 或 `❌`；未受影响的模块可合并为一条 `➖ 模块：未受影响（原因）`。
- 任一项为 `❌` 时，输出完整的适用项结果和失败汇总，不执行提交或推送。
- 全部通过后才继续。提交备注正文加入 `Checklist` 段落；仅推送时不改写提交，在结果中输出 Checklist。
- Checklist 是门禁记录，不能替代构建、测试和代码 review。
