# 创建真实 Demo 验证 iOS 工作流

## 原始需求

增加一个真实 Demo 项目，完整验证当前 iOS 工作流。

## 需求分析

- 目标：用可运行的业务项目验证需求、设计、项目生成、实现和测试链路，而不是新增工作流验证工具。
- 范围：新建 `WorkflowDemo`；首页提供计数增加与重置；设置页提供语言切换和关于我们；生成 Xcode 工程；覆盖单元测试、UI 测试和模拟器构建。
- 验收标准：首次启动显示计数 0；点击增加后显示计数 1；点击重置后恢复为 0；可从首页进入设置和关于我们；可在跟随系统及 12 种语言间切换，选择被持久化且当前界面立即刷新；项目可由 XcodeGen 生成并完成无签名模拟器构建；单元和 UI 测试通过。
- 非目标：网络、持久化、三方依赖、订阅、打点及发布上架。
- 状态与异常：功能完全本地运行，无加载、离线、权限和网络错误状态；计数达到 `Int.max` 时不再增加。
- 影响：新增 Swift/UIKit/MVVM 项目、本地化、Dynamic Type、VoiceOver、UserDefaults 语言偏好、单元测试、UI 测试和隐私清单；无外部数据迁移和 API。
- 风险与假设：本机无 CocoaPods，因此显式使用 `none`；使用当前已安装的 XcodeGen 与 Xcode 验证。生成或测试失败时保留首个可行动错误。
- 完成定义：需求与项目台账已记录；代码、配置、工程和测试齐全；生成器测试、Demo 构建、单元测试和 UI 测试取得证据。

## 技术方案

- 设计等级：`full`，因为这是包含 App、单元测试与 UI 测试多个 target 的新项目。
- 候选方案：仅保留生成器默认首页；创建依赖网络的列表 Demo；创建纯本地计数 Demo。
- 采用纯本地计数 Demo：它能验证生成、MVVM 状态变化、UI、本地化、无障碍和测试，同时不引入外部服务造成不稳定。
- 不采用默认空首页，因为缺少真实交互和业务测试；不采用网络列表，因为外部状态会削弱工作流验证的确定性。
- 语言、UI 与架构：Swift 5.10、UIKit、MVVM、iOS 14.0；`HomeViewModel` 持有计数和边界规则，`HomeViewController` 只展示状态并转发操作。
- 模块与状态流：`Features/Home` 维护计数；`Features/Settings` 展示语言和关于入口；`Features/Language` 选择语言；`Features/About` 展示静态应用信息。语言改变后发布应用内通知，各可见页面立即重新本地化。
- 数据、并发与错误：无 API 或并发；`Int.max` 使用不变状态处理；语言选择通过 `UserDefaults` 持久化，非法旧值回退跟随系统。
- 依赖：`none`；仅使用 UIKit 与 XCTest。
- 本地化与无障碍：文案来自各语言 `Localizable.strings`；使用 Dynamic Type、语义颜色、系统按钮和稳定 accessibility identifier。
- 隐私、安全、订阅与打点：无采集、权限、订阅和打点；保留生成的空隐私清单。
- 测试：ViewModel 覆盖初始、增加、重置和上限；语言偏好覆盖默认、保存及非法值回退；UI 测试覆盖计数、语言切换和关于页面；执行无签名模拟器构建和受影响测试 target。
- 兼容、发布与回退：兼容 iOS 14；不发布；失败时可删除整个新增 Demo，不影响工作流仓库。
