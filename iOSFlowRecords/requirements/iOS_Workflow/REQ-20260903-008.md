## 原始需求

再次检查并优化仍可减少的 Token 使用。

## 需求分析

- 目标：降低低风险任务、新项目、恢复、重复验证和 Git 交付的上下文与操作开销。
- 范围：任务路由、项目生成、证据复用、活动摘要、Git 关联、模板、文档和测试。
- 验收标准：低风险任务不固定加载完整需求/设计规范；生成器直接消费配置；活动索引足以恢复；无关文档不使测试证据失效；禁止交付状态回写提交。
- 非目标：不削弱高风险设计、测试失败处理或条件门禁，不修改业务项目。
- 风险：按需加载可能遗漏边界；通过明确 full 设计触发条件和按影响加载回退控制。

## 技术方案

- 设计等级：`full`，因为变更跨入口、生命周期、生成器边界、测试和 Git 门禁。
- 采用条件路由与工具消费配置，保持高风险规则按需可达。
- Git 仓库和远端引用作为交付事实来源，消除自引用记录提交。
- 索引 v3 增加恢复所需字段，档案摘要前移作为回退。
