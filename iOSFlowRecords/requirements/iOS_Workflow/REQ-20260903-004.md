# 增加测试与质量保障模块

## 原始需求

执行完整 iOS 工作流中项目生成之后的下一步。

## 需求分析

- 目标：让功能实现后的测试范围、执行顺序、失败处理和验收证据保持一致且可恢复。
- 范围：测试策略、测试计划与报告模板、提交门禁、任务路由和团队使用说明。
- 验收标准：测试任务按风险选择层级和设备矩阵；结果包含可复核证据；失败与 flaky test 不会被静默忽略；提交门禁只在相关 diff 中加载该模块。
- 非目标：不绑定第三方测试平台，不设脱离项目基线的统一覆盖率数字，不新增用户 CLI。
- 状态与异常：覆盖测试工具缺失、编译失败、测试失败、模拟器不可用、超时和不稳定测试。
- 影响：更新工作流规则、模板、Checklist 和文档；不修改业务 UI、依赖、订阅或打点。
- 风险与回退：规则过重可能增加耗时，因此按风险选择最小矩阵并复用未失效证据；可回退到上一工作流 tag。
- 完成定义：规则、模板、路由、文档和结构测试一致，相关自动化测试通过，提交另行触发。

## 技术方案

- 设计等级：`full`，因为测试策略横跨需求、实现、构建、设备矩阵和提交门禁。
- 候选方案：只扩充通用 Checklist；建立单一测试规范；建立规范、计划/报告模板和条件门禁组合。
- 采用组合方案：规范定义决策和失败处理，模板保存高风险或跨会话证据，Checklist 负责提交前核对；不把全部测试信息塞入入口文件。
- 模块边界：`standards/testing.md` 负责执行策略，`templates/testing/` 负责持久化格式，`checklists/testing.md` 负责门禁，AGENTS 只负责条件路由。
- 状态流：影响分析 → 测试计划 → 依赖/构建准备 → 分层测试 → 失败分类与有限复跑 → 测试报告 → 提交门禁。
- 数据与隐私：测试数据使用非生产、可清理夹具，不保存令牌、账号、个人数据或完整敏感日志。
- 依赖：不新增第三方依赖；沿用 XCTest、xcodebuild 和项目既有工具。
- 验证：增加工作流结构测试，并运行完整 unittest；文档规则使用 diff 检查。
