# 测试与质量 Checklist

代码、测试、项目配置、依赖、生成器或验收行为发生变化时执行。

- Requirement 验收标准与测试层级、场景和证据可以逐项对应。
- 测试范围优先覆盖 diff、边界、错误和高风险路径，没有用无关全量矩阵消耗时间。
- Xcode、scheme、configuration、destination、依赖锁和测试选择已明确；需要多设备或系统版本时已扩展矩阵。
- 受影响 target 的静态检查、编译和必需测试已执行，结果与当前证据键一致。
- UI、本地化、无障碍、性能、隐私、订阅和打点专项只在受影响时执行或明确标记 `➖`。
- 失败已按环境、依赖、编译、断言、崩溃、超时或 flaky 分类，没有通过跳过、放宽断言或无限重试伪造通过。
- flaky 确认最多额外复跑一次；新增不稳定测试已阻止交付，既有隔离项具备负责人、跟踪项和到期时间。
- 测试数据不包含生产令牌、支付资料或个人数据；报告不保存无关完整日志。
- 结果摘要包含通过、失败、跳过、证据位置、未覆盖项和残余风险；必需证据缺失时标记 `❌`。
