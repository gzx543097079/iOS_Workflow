# iOS UI 规范

## 基线

- 优先系统组件和平台习惯，内容优先，交互名称、位置和反馈保持一致。
- UI 参数来自 `config/design-tokens.jsonc`；业务页面不复制颜色、间距、字号、圆角和动效常量。
- 尊重 safe area、键盘、横竖屏和尺寸变化；大屏限制内容宽度，点击区域至少 44×44 pt。

## 视觉与组件

- 使用系统字体和 text styles，支持 Dynamic Type；不以固定高度裁切文本。
- 使用语义色并支持深色模式；状态不能只靠颜色表达，文本和关键图形满足 WCAG AA。
- 导航、tab bar、sheet、alert 和 context menu 优先用系统实现。
- 按钮文案说明结果；破坏性操作使用对应语义并按风险确认。
- 表单标签持续可见，错误紧邻字段；placeholder 不替代 label。

## 状态与反馈

- 数据页面覆盖初始、加载、内容、空、可恢复错误，以及适用的离线或权限受限状态。
- 操作即时反馈，耗时任务防重复提交；可预测进度使用 determinate progress。
- 动效解释状态变化并尊重 Reduce Motion；触觉只用于确认、警告或明显状态变化。

## 可访问性与本地化

- 非装饰内容提供准确 accessibility label；VoiceOver 顺序、traits 和 actions 正确。
- 支持大字号、粗体、提高对比度和减少动态效果，并用 VoiceOver 完成主流程。
- 文案使用本地化资源，不拼接句子；布局容纳至少 30% 文本扩展和超长内容。
- 使用标准语言标识；RTL 使用 `leading/trailing`，单独检查导航、图标、对齐和混排。
- 海外 app 默认评估英语、西班牙语、法语、德语、日语、韩语、巴西葡萄牙语、意大利语、阿拉伯语和俄语，实际范围按市场确定。
- 交付前检查浅色/深色、至少三档字号、小屏/大屏、空/错/离线/拒绝权限状态。
