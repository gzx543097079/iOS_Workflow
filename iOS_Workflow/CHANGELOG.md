# Changelog

## 3.7.0 - 2026-09-03

- 低风险明确任务使用上下文需求卡和 inline brief，完整需求与技术设计规范改为条件加载。
- 新项目生成时由生成器直接消费配置，避免默认把九份规则和配置全部载入模型上下文。
- 活动索引包含完整恢复摘要，测试证据仅由受测输入失效，纯文档和记录变化不触发重跑。
- Git 交付状态改为从仓库和远端实时查询，禁止为回写当前提交 hash、推送或 tag 状态制造额外提交。

## 3.6.0 - 2026-09-03

- 限定需求持久化条件，低风险单轮任务不再因开始执行而创建运行档案。
- 将活动索引压缩为单个摘要和最后使用 ID，恢复时优先读取 `恢复摘要` 与首个未完成步骤。
- 简单新增页面或内部模块允许使用 brief 设计，并将需求完成状态与 Git 提交、推送状态解耦。

## 3.5.1 - 2026-09-03

- 示例仓库开始跟踪 `iOSFlowRecords`，使需求、项目顺序和测试证据可随 Git 提交共享。
- 删除与仓库实现不一致的 `REQ-20260903-005` 需求及关联测试记录，并保留已使用序号不复用。

## 3.5.0 - 2026-09-03

- 增加真实 `WorkflowDemo`，覆盖项目生成、UIKit/MVVM 计数功能、设置、运行时语言切换、关于我们、单元测试和 UI 测试。
- 修复 UIKit 新项目 Scene Manifest 缺少 SceneDelegate 配置导致启动后白屏的问题。

## 3.4.0 - 2026-09-03

- 增加测试与质量保障模块，统一验收映射、测试分层、最小设备矩阵、证据复用和结果报告。
- 增加环境阻塞、失败分类和 flaky test 有限复跑规则，以及测试计划、报告模板和条件门禁。

## 3.3.0 - 2026-09-03

- 增加内部 iOS 项目生成与配置校验模块，支持 Swift/UIKit、Swift/SwiftUI 和 Objective-C/UIKit。
- 从配置生成架构、导航、本地化策略、中文注释、DesignTokens、测试、隐私清单和 XcodeGen 工程设置。
- 增加项目生成专项规范、提交门禁和自动化测试，并验证三种支持组合可完成模拟器编译。

## 3.2.0 - 2026-09-03

- 增加 brief/full 技术设计分级、Feature/Bug Fix/ADR 模板和编码前设计门禁。

## 3.1.0 - 2026-09-03

- 增加需求分析与任务定义规范，以及按需加载的 Feature 和 Bug 需求模板。
- 增加可见的 `iOSFlowRecords/` 需求台账，支持跨会话恢复、执行步骤、Git 关联和需求追溯门禁。
- 增加项目级需求执行台账，以固定顺序记录所有开始执行过的需求及其状态和提交。

## 3.0.0 - 2026-09-03

- 支持将完整工作流放入任意工作目录的 `iOS_Workflow/` 子目录，并由同级轻量 `AGENTS.md` 统一引入；`Workspace` 不再作为固定目录名。
- 同一任务内对规则文件去重，并避免重复加载已经进入上下文的完整入口。
- 依赖状态和 diff 未变化时复用安装、构建、测试及静态检查证据。
- 提交后立即推送时只执行增量检查，避免重复 Checklist 和 Git 正文输出。
- 将 Swift 与 Objective-C 细则从核心规范拆出并按语言加载，同时压缩运行时规则的重复表述。

## 2.0.3 - 2026-09-02

- 将运行时规则改为按任务路由，避免每次任务加载全部规范。
- 将代码规范拆分为核心、代码生成和三方依赖三个模块。
- 将提交门禁拆分为通用、订阅和数据打点模块；后两者仅在 diff 影响相关功能时读取。
- 将各规范的历史记录集中到本文件，缩短运行时上下文。
- 依赖安装、解析和编译成功时使用摘要输出，失败时只保留相关日志。

## Code standards

- 1.5：要求新项目创建、三方库版本变化和编译前执行对应依赖操作；直接依赖必须精确锁定版本。
- 1.4：明确生成代码注释边界和 pod、SPM、Carthage、none 的依赖方式。
- 1.3：增加提交、推送和 review 的自动 Checklist 门禁。
- 1.2：移除不再需要的 CLI 使用方式。
- 1.1：补充命名和英文大小写约定。
- 1.0：建立 Swift、Objective-C、架构、日志、隐私和测试基线。

## UI standards

- 1.3：增加海外 app 常用语言、标准语言标识和 RTL 专项检查要求。
- 1.2：配置文件升级为带字段注释的 JSONC 格式。
- 1.1：统一 app、text styles、系统组件、代码标识符和计量单位的英文格式。
- 1.0：建立布局、排版、颜色、组件、状态、动效和可访问性基线。
