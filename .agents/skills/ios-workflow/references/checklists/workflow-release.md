# 工作流包发布 Checklist

仅在实际发布对象为 iOS Workflow 规则包时读取，由调用方显式指定 `release_target=workflow`；文件名或 CHANGELOG 不决定发布对象。普通发布自动化修改按本次影响验证；实际发布时完成以下检查。业务 App 发布仍使用[App 发布清单](release-distribution.md)。

## 发布准备

- [ ] 版本、CHANGELOG、预期源提交和拟发布 Tag 一致；阶段提交与正式发布分开，不覆盖已有不同内容的版本。
- [ ] 当前发布源码的 Python 工作流测试通过，分发包链接及独立安装检查通过；失败或未运行如实记录。
- [ ] 已取得当前生成器及受影响模板对应的 macOS 无签名 `build-for-testing` 成功证据：Swift + UIKit 与 Swift + SwiftUI 各覆盖 Swift 5、Swift 6，Objective-C + UIKit 覆盖一组，共 5 case。记录实际 Xcode/SDK 和测试选择，不用 Python 文本断言代替生成工程编译。
- [ ] 当前 Demo 的单元与 UI 模拟器测试实际执行并通过，记录所选 Xcode、系统与设备，以及测试数量和 `.xcresult`；编译通过不代替运行结果。
- [ ] ZIP 来自已核对的源码与版本；最外层包含配置示例、字段说明、接入说明和版本标记。包内 Skill、引用与辅助脚本完整，不混入业务记录、凭据、缓存或无关产物。
- [ ] ZIP 的 SHA-256 与发布校验文件一致，压缩包可独立解包、加载引用和导入辅助接口；重新生成包时重新核对摘要。
- [ ] 已核对目标仓库、远端和已有同名 Tag；当前本地提交与拟推送内容明确，没有把尚未执行的推送记为成功。

## 授权动作及结果

- [ ] 按当前授权推送后核对远端分支与 Tag 指向的实际提交。尚未推送或远端不可达时明确为待同步，不能声称已发布。
- [ ] 创建或更新 GitHub Release 及上传附件在用户当前授权内。外部步骤完成后核对真实发布状态、Tag、ZIP 与校验文件，不把本地打包成功当作远端已发布。

此流程不要求 Bundle ID、Team、证书、App Store Connect、业务需求账本或业务完成状态。`assess_gate(..., release_target='workflow')` 的 `validation_result` 对应实际测试与生成编译结果，`release_result` 只对应前述“发布准备”的版本、包内容、校验和与 Git 输入检查；两者都通过才允许进入授权发布动作。发布后的远端状态仍须实际核对，不用准备阶段的通过结论代替，也不要求先完成远端动作才能通过准备检查。
