# 需求追溯 Checklist

- [ ] 实施整份需求文档、跨设备或其他需持久化的任务已建档；低风险普通维护不适用时说明原因。
- [ ] 当前业务项目和 Requirement ID 匹配；实际记录位于该项目 `.ios-workflow/`，工作流目录只保留规则和模板。
- [ ] 外部需求来源在项目内有可恢复副本或快照；所有来源、实现、证据引用均为项目根目录相对路径。
- [ ] 原始要求均有稳定验收 ID 或有依据的范围排除；未知内容、P1 和非目标没有被静默删除或当作已授权实施。
- [ ] 已执行需求存在于项目台账，顺序号与档案一致；无需求 ID 碰撞、重复或丢失的并行记录。
- [ ] 本次 diff 没有超出授权范围；范围、验收及技术选择变化已保留决定来源与影响。
- [ ] 本次完成的 STEP ID、验收 ID、实际修改和验证证据一致；设计等级及状态满足当前任务要求。
- [ ] `.ios-workflow/progress.json` 结构、项目相对路径与证据及输入哈希校验通过；没有把结构校验当作业务验收通过。
- [ ] `verified` 项有实际取得且适用于当前内容和环境的成功证据；未运行、缺失或失效证据没有被标记通过。
- [ ] 需求档案和账本不把配置声明、工程生成、编译成功或测试骨架误记为全部业务功能完成；后续不读取、不核对首次生成配置。
- [ ] 延期、取消和排除项有范围决定，未通过删除或改状态掩盖未完成需求。
- [ ] 本次要求 Git 交付时，提交正文包含 `Requirement` 和 `Steps`；不适用时说明原因。
- [ ] 阶段边界或完成后，活动索引、需求档案、账本和项目台账一致；交接摘要明确下一动作、阻塞和待同步内容。
- [ ] 代码、必要记录和精简证据可随项目 Git 恢复；离线、未提交、未推送、合并冲突或远端不可达已明确，未声称跨设备已完整同步。
- [ ] Git 交付状态从提交日志、上游和远端引用实时判断，没有为回写当前提交 hash、推送或 tag 状态制造额外提交。
- [ ] 只有本次完成定义和必需验收全部满足时才标记 `done`；`done` 不依赖是否已提交或推送，远端已同步另行核实。
