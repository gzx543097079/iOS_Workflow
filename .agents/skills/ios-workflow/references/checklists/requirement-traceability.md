# 需求追溯 Checklist

- [ ] 当前项目和活动 Requirement ID 匹配；没有关联需求的维护操作已说明原因。
- [ ] 已执行需求存在于项目台账，顺序号与需求档案一致且没有重排或重复。
- [ ] 本次 diff 没有超出需求范围；范围变化已写入需求变更记录。
- [ ] 本次完成的 STEP ID、实际修改和验证证据一致。
- [ ] 需求的设计等级和状态已记录，执行步骤来自已确认设计；实现偏差已同步。
- [ ] 受影响的验收标准已验证，未完成项没有被提前标记。
- [ ] 本次要求 Git 交付时，提交正文包含 `Requirement` 和 `Steps`；不适用时说明原因。
- [ ] Git 交付状态从提交日志、上游和远端引用实时判断，没有为回写当前提交 hash、推送或 tag 状态制造额外提交。
- [ ] 阶段边界或需求完成后，活动索引摘要、需求档案和项目台账保持一致。
- [ ] 只有完成定义全部满足时，需求状态才标记为 `done`；`done` 不依赖是否已提交或推送。
