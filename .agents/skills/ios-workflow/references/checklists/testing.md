# 测试与质量 Checklist

代码、测试、项目配置、依赖、生成器或验收行为发生变化时执行。

先按当前操作解释检查项：普通提交、推送、review 和验收交付要求相关验证通过；`checkpoint` 检查验证记录真实且可恢复，允许保存已知失败、阻塞和未执行范围，不把它们标为通过。范围、隐私、用户文件保护或记录完整性问题始终阻止保存。

- Requirement 验收标准与测试层级、场景和证据可以逐项对应。
- 测试范围优先覆盖 diff、边界、错误和高风险路径，没有用无关全量矩阵消耗时间。
- 实际执行的 Xcode、scheme、configuration、destination、依赖锁和测试选择已明确；需要多设备或系统版本时已扩展矩阵。checkpoint 中尚未执行或无法核实的环境明确写未知，不补造环境。
- 受影响 target 的静态检查、编译和必需测试结果与当前证据键一致；checkpoint 中未执行的部分有明确待办与下一步。
- UI、本地化、无障碍、性能、隐私、订阅和打点专项只在受影响时执行或明确标记 `➖`。
- 失败已按环境、依赖、编译、断言、崩溃、超时或 flaky 分类，没有通过跳过、放宽断言或无限重试伪造通过。
- flaky 确认最多额外复跑一次；新增不稳定测试阻止验收交付，仍可如实保存阶段记录；既有隔离项具备负责人、跟踪项和到期时间。
- 测试数据不包含生产令牌、支付资料或个人数据；报告不保存无关完整日志。
- 结果摘要包含通过、失败、跳过、证据位置、未覆盖项和残余风险；普通交付的必需证据缺失构成门禁 `❌`。checkpoint 真实登记的验证失败或未知不自动阻止保存，记录丢失或虚构结果仍阻止。
