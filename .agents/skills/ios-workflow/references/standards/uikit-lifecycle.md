# UIKit 生命周期与状态

用于新增或修改控制器生命周期、页面状态、列表复用、订阅与异步刷新；静态文案和颜色调整沿用 [UI 规范](ui-style.md)，无需加载本模块。适用于 Swift 与 Objective-C，保持项目当前控制器、ViewModel、路由和数据层边界。

## 找到正确的拥有者

- 先检查当前页面及其导航容器、数据提供方和 App/Scene 入口。沿用工程是否启用 scene 的事实，不为本次页面修改引入入口迁移；页面可见状态、scene 活跃状态与进程生命周期分别处理。
- 业务状态归现有模型或 ViewModel，控件从状态渲染；避免控制器、cell 和数据层各保存一份可变业务状态。需保留筛选、输入或选中项时，明确导航返回后由谁恢复。
- 布局初始化与可重复出现分开：为当前 view 实例安装子视图、约束和绑定的代码应避免重复；出现回调里的刷新须处理再次出现、转场取消和重复触发。不要把一次出现等同于一次业务创建。

## 生命周期边界

- 明确请求、通知观察、定时器和订阅的有效范围。按拥有者结束范围解除或取消；页面暂时被覆盖不等于对象销毁，也不代表上传等业务任务必须取消。检查闭包与任务持有关系，不能只添加 `weak self` 就宣称泄漏修复。
- cell 重用或重新配置时清理本 cell 的旧请求和临时展示状态；异步返回核对当前 item 身份，避免快速滚动后图片或状态串位。业务结果保存在数据层，不依赖仍可见的 cell。
- 避免用过期的 index path 定位异步结果对应模型；使用项目已有稳定标识。结构更新与渲染使用同一份状态，防止列表更新期间数量不一致。
- 自定义容器需要完整建立与解除父子控制器关系，让 UIKit 正确分发外观事件；普通导航优先沿用已有容器，不手动转发系统已经负责的生命周期。
- UI 写回遵守当前主线程或主 actor 约定；涉及 Swift 隔离、取消及乱序结果时再读 [并发诊断](swift-concurrency.md)。

## 验证

按本次改动选择最小可复现场景：反复进入返回、取消交互转场、切换 tab、前后台切换、列表快速复用或请求乱序。核对保留状态、请求次数、事件订阅和结果归属；改动对象释放逻辑时再检查释放。无需为静态 UI 改动执行全部生命周期场景。

参考：[UIViewController](https://developer.apple.com/documentation/uikit/uiviewcontroller)、[App 与 Scene 生命周期](https://developer.apple.com/documentation/uikit/managing-your-app-s-life-cycle)。
