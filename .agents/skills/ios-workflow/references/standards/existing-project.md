# 已有 iOS 工程接入与维护

仅在已有工程首次接入、工程结构或依赖变化，或构建入口与环境不明确时读取；已知工程中的普通方法修改不额外加载。本模块维护当前工程，不读取、核对、补建或迁移首次生成配置。

## 确认工程定义来源

- 结合项目约定、现有 CI／构建脚本和实际文件，确认 App 所属 project／workspace、scheme、受影响 targets、依赖清单与锁文件，以及实际工具环境。只读取本次相关部分；必要时用已安装工具查询工程信息，不猜测默认 scheme。
- 分清持续维护的定义与生成产物，确认现有命令实际读取哪些文件、更新哪个工程。`project.yml`、`Project.swift`、`Package.swift` 的存在都只是线索；依赖包的 manifest 不自动成为 App 入口，文件名也不能证明项目已采用某工具。
- 多个入口、过期定义或项目约定冲突时，明确已知事实与缺项，先解决影响写入或构建的歧义；其他独立工作继续。工具不可用时说明阻塞，不通过切换工程维护方式绕过问题。

## 沿用当前维护方式

| 已确认的维护方式 | 本次修改的来源与处理 |
| --- | --- |
| XcodeGen | 维护当前实际使用的 `project.yml` 及其引用定义；它们是持续维护的工程源，不是一次性生成输入。先校验定义，再按项目已有生成命令更新工程并审阅 diff；不只修改会在下次生成时丢失的 `project.pbxproj`。 |
| Tuist | 沿用当前 manifests、辅助定义和项目生成命令，检查受影响 targets 与生成 diff；不迁移为 XcodeGen。 |
| SwiftPM | 维护实际所属的 `Package.swift`、target 源码与资源及依赖锁，沿用项目构建入口；App 另有 Xcode 工程时仍维护其集成，不把整个 App 当成依赖包处理。 |
| 手工维护的 Xcode 工程 | 沿用当前 `.xcodeproj`／`.xcworkspace`、scheme 和工程设置，通过 Xcode 或项目已有可靠方式做必要修改；不新建生成定义或重建整个工程。 |

生成命令只在已确认适用且本次成员、targets、设置或依赖变化需要时执行；接入 Skill 或普通方法修改不要求重生成。生成或修改工程前检查当前 diff，保留用户已有修改。生成产物存在手改或来源不明差异时先协调到维护源，或在隔离目录生成比较；无法保留时停止相关更新，不能用生成器直接覆盖。

更新后检查来源定义与工程 diff 是否仅包含预期变化，确认源文件和资源进入正确 target，scheme、构建设置与依赖关联仍有效，再执行受影响 target 的最小相关验证。依赖解析按[依赖规范](dependencies.md)，测试范围按[测试规范](testing.md)选择；没有实际执行的验证如实说明。
