# 需求追踪入口

本规范主要用于 iOS 业务项目。工作流只提供规则、脚本和模板；实际需求、方案、进度、交接、测试报告与必要证据统一保存在 `<业务项目根目录>/.ios-workflow/`，不写入 Skill、工作流发布包或多个项目共用的工作目录。该目录是本工作流约定，不属于 Codex 官方 Skill 结构。先确认实际工程所属的项目根；同一工作区的多个业务项目各自建档，不按客户端当前工作目录猜测项目归属。

需求状态使用 `draft`、`ready`、`in_progress`、`blocked`、`done`、`cancelled`；验收项另用 `pending`、`in_progress`、`implemented`、`verified`、`blocked`、`deferred`、`cancelled`。实现、验证完成与 Git 同步分别判断，缺失证据不能当作通过。

## 按需读取

只读取当前动作对应的模块；已明确任务时直接进入该模块，不依次加载全部生命周期规则。

| 当前动作 | 读取模块 |
| --- | --- |
| 确定是否建档、创建项目内记录、分配需求 ID 或首次执行顺序 | [建档与状态](tracking-start.md) |
| 登记或变更验收项、核对证据、判定需求完成 | [验收与证据](tracking-evidence.md) |
| 执行、继续、阻塞或更新阶段摘要 | [执行与恢复](tracking-resume.md) |
| 跨设备交接、Git 关联或核对远端同步 | [跨设备与 Git](tracking-sync.md) |
| 仅查看已执行需求或执行顺序 | [查询执行历史](tracking-sync.md#只查询执行历史) |

首次生成配置仅用于首次生成；已有项目的后续工作不读取、不核对初始生成配置。
