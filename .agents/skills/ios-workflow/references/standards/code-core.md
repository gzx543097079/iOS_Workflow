# iOS 核心代码规范

## 基线与命名

- 遵循 Apple 官方指南和项目现状；使用 4 空格、UTF-8、LF，处理新增警告。
- 不无理由引入第二套架构或基础设施；业务模块保持 `Features/<Feature>` 边界。
- 类型用 `UpperCamelCase`，方法、属性和变量用 `lowerCamelCase`；Bool 使用 `is/has/can` 等可读前缀。
- 名称表达业务含义，避免宽泛的 `data`、`info`、`manager`、`handler`；协议表达能力或角色。
- 文件名与主类型一致，扩展使用 `Type+Purpose`。平台、框架、技术缩写和源码标识符保持官方大小写。

## 架构

- View 只展示和转发事件，不直接处理网络、存储或复杂业务。
- Model 表达领域数据；状态转换和协调遵循项目已有的 ViewModel、Presenter 或 Controller 边界。
- 外部依赖优先注入；公共 API 小而稳定，跨模块通过明确接口访问。
- 并发任务处理取消、重复请求、生命周期和错误恢复。

## 错误、日志与隐私

- 使用有含义的错误类型，不以字符串判断或静默吞错；用户文案与诊断信息分离。
- 使用项目日志设施或 `Logger`，不遗留 `print`，不记录令牌、密码、支付信息或个人敏感数据。
- 权限仅在需要时请求并说明用途；订阅、支付、账户和打点遵守最小采集及项目隐私约定。

## 测试与交付

- 新逻辑覆盖正常、边界和错误路径；缺陷修复应复现问题或增加回归测试。
- 测试名表达条件和结果，例如 `test_load_whenRequestFails_showsRetryState`。
- 只交付当前任务相关修改，不覆盖用户的无关变更。
