# 团队接入

1. 在临时目录解压发布包，通过 `IOS_WORKFLOW_VERSION` 确认版本，并确认其中包含 `.agents/skills/ios-workflow/`、`AGENTS.ios-workflow.example.md`、最外层配置示例及字段说明、版本标记和本说明。
2. 将 `.agents/skills/ios-workflow/` 复制到业务仓库根目录的相同路径；更新已有版本时先检查差异，再替换该 Skill 目录。
3. 业务仓库没有 `AGENTS.md` 时，将示例改名为 `AGENTS.md`；已有该文件时只合并适用规则，不覆盖项目约定。
4. 在 Codex 中打开业务仓库根目录，并提交 `.agents/skills/ios-workflow/` 与 `AGENTS.md`，让团队成员使用同一版本。

`.ios-workflow/` 是各业务项目运行时按需创建的状态目录，不包含在发布包中，也不要从工作流仓库复制历史记录。

## 从需求文档生成项目

将 iOS 需求文档交给客户端，由客户端提取选型并按最外层 `project.example.jsonc` 的结构保存项目配置，不要求团队先手工填写。也支持自行复制示例修改。生成配置、原始需求和执行记录均放入目标业务项目 `.ios-workflow/`；首次生成允许目录仅含该记录目录和普通 Git/Skill 接入元数据，不覆盖已有业务代码。

配置仅首次生成使用，后续版本按实际工程和当前需求开发。已有项目接入不要求生成配置，但执行文档或跨设备任务需建立项目内需求追踪。

## 跨设备继续

需求、进度、交接和轻量证据与业务代码一起纳入项目 Git；大型日志和构建放 `.ios-workflow/artifacts/` 并忽略。切换设备前保存并在已有授权范围内提交、推送；没有同步成功不能宣称另一设备已收到。新设备核对分支、HEAD、工作区和证据后继续，缺失信息标记待核验，不猜测进度。工作流目录不保存任何业务项目运行状态。
