# iOS UI 规范 v1.3

## 设计原则

- 优先使用 Apple 平台习惯与系统组件，让界面清晰、可预期、可访问。
- 内容优先于装饰；层级通过排版、间距和系统材质表达。
- 同一操作在全 app 使用一致的名称、位置、图标与反馈。
- UI 规范通过 `config/design-tokens.jsonc` 参数化；业务页面不得复制一套私有 token。

## 布局与间距

- 以 4 pt 为基础网格，常用间距为 8、12、16、24、32 pt。
- 页面标准水平边距 16 pt；大屏内容区域建议限制最大宽度并居中。
- 尊重 safe area、键盘、Dynamic Type 和横竖屏变化，不依赖固定屏幕尺寸。
- 最小可点击区域为 44×44 pt；相邻主要操作保留足够误触距离。

## 排版

- 使用系统字体与 text styles，如 `largeTitle`、`title`、`headline`、`body`、`caption`。
- 支持 Dynamic Type，不用固定高度裁切文本。
- 正文优先左对齐；数字表格可按语义对齐。
- 颜色不能成为传达状态的唯一手段，同时提供文本、形状或图标线索。

## 颜色与外观

- 使用语义色（`label`、`systemBackground`、`separator` 等），完整支持深色模式。
- 品牌强调色只用于关键交互、选中态与少量强调，避免大面积滥用。
- 普通文本和关键图形需满足 WCAG AA 对比度目标。
- 禁用态仍需可辨识，不单纯靠极低透明度。

## 组件

- 导航优先采用系统 navigation、tab bar、sheet、alert 与 context menu。
- 按钮文案使用动词并描述结果；破坏性操作使用 `destructive` 语义并在必要时确认。
- 表单标签持续可见，placeholder 不替代 label；错误紧邻字段并说明修复方式。
- 空状态包含现状、原因（必要时）和一个明确下一步。
- 加载超过约 300 ms 时展示反馈；可预测进度使用 determinate progress。

## 状态与反馈

每个数据驱动页面明确设计以下状态：

1. 初始态
2. 加载态
3. 正常内容态
4. 空态
5. 可恢复错误态
6. 离线或权限受限态（适用时）

操作应即时反馈；耗时任务防止重复提交，同时不要无故冻结整个页面。

## 动效与触觉

- 动效用于解释状态变化，常规时长建议 0.2–0.3 秒。
- 尊重 Reduce Motion；关闭非必要位移与视差。
- 触觉反馈只用于确认、警告或明显状态变化，不为每次点击添加。

## 可访问性与本地化

- 所有非装饰性图标和图片提供准确的 accessibility label。
- VoiceOver 顺序与视觉阅读顺序一致；自定义控件提供正确 traits 和 actions。
- 支持更大字号、粗体文本、提高对比度、减少动态效果。
- 文案使用本地化资源，不拼接自然语言句子；布局允许文本扩展 30% 以上。
- 支持 RTL 时使用 `leading`/`trailing`，不硬编码 `left`/`right`。
- 面向海外市场的 app 默认评估英语、西班牙语、法语、德语、日语、韩语、巴西葡萄牙语、意大利语、阿拉伯语和俄语；实际启用范围由目标市场决定。
- 本地化目录使用标准语言标识，例如 `en`、`pt-BR`、`zh-Hans`；不要用展示名称或自定义缩写代替。
- 阿拉伯语等 RTL 语言必须单独检查导航方向、图标语义、文本对齐和混排内容，不只验证字符串翻译。

## 交付检查

- 在浅色/深色、至少三档字号、小屏和大屏设备检查。
- 检查加载、空、错误、离线、权限拒绝与超长文本。
- 用 VoiceOver 完成主流程，并确认所有点击区域达到 44 pt。
