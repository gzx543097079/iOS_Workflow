# 生成代码与中文注释规范

本规范仅约束新建项目或本次任务新生成的手写代码，不要求对已有代码追溯补注释，也不要求在后续 checklist 中机械匹配。

注释默认使用中文，等级默认为 3；新项目以 `config/defaults.jsonc` 的 `comment_level` 为准，已有项目以项目配置或用户当前要求为准：

1. 不生成解释性注释。
2. 使用自然语言说明页面或文件的用途。
3. 在等级 2 基础上，说明业务自定义方法的作用、Model 的用途，以及较难实现的思路和关键取舍。
4. 在等级 3 基础上，补充重要属性、关键控制流、边界条件和错误处理说明。

所有等级共同遵守：

- 不为系统方法、系统协议实现、系统生命周期方法、系统 delegate/data source 方法或继承自系统类的方法生成解释性注释。
- 不生成文件名、项目名、创建时间、作者、Git 分支或提交信息等文件头。
- 不使用“类型职责”“方法职责”“Model 职责”等模板化标签。
- 不逐行复述代码，不为显而易见的赋值、布局和简单转发添加噪声注释。
- 注释解释意图、约束和非显然原因；代码能清楚表达的信息交给代码本身。
